# 使用场景与可交付结果

这些场景用于理解技能的边界，不代表任何具体项目已经通过验收。

## 场景一：跨端功能开发

**输入**

“在现有 Web、管理端和 API 中增加一个订单处理功能，保留已有权限和分页逻辑。”

**技能动作**

1. 读取仓库规则、工作区状态和真实调用路径。
2. 建立任务契约，标出身份、状态、分页、错误和兼容约束。
3. 优先补齐一个从入口到持久化结果的闭环，再检查各端是否真正接线。
4. 依次报告自动化、本地、集成和设备证据。

**交付结果**

变更文件、受保护契约、执行过的验证、未执行项、提交或发布状态均可复核。单端完成时不会把整个跨端功能写成全部完成。

## 场景二：收费订单接线

**输入**

“客户端接入收费订单；金额使用整数分，订单已有版本号，回调已有 Inbox 去重，历史订单不能随新费率变化。”

**技能动作**

1. 保留金额精度、CAS、幂等和历史快照语义。
2. 区分授权的客户端接线与未授权的真实数据库迁移。
3. 指定环境字段漂移时保留失败证据；隔离库通过不能覆盖真实环境失败。
4. 继续完成不依赖阻断环境的授权工作。

**交付结果**

明确列出已完成的接线、真实环境阻断、需要的额外权限和下一步验收方式。

## 场景三：判断候选版本能否上线

**输入**

“类型检查、测试和构建通过；真实服务测试被跳过；线上健康接口正常，但当前提交尚未部署；生产包仍含 localhost 回退地址。”

**技能动作**

1. 将构建通过、真实集成未执行、线上旧版本健康和候选未部署分别记录。
2. 先处理产物配置，再验证指定环境、设备流程、部署版本和发布后回归。
3. 不主动部署，也不把旧报告或单端气泡当作当前候选的全链路证据。

**交付结果**

给出“当前不能确认上线”的证据化判断，以及按风险排序的剩余项。

```text
使用 $software-general-engineering 完成这次跨端修改。先保护现有工作和接口契约，再按证据层级验证，最后分别说明代码、集成、设备和发布状态。
```
